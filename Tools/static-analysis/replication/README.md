# Replication package — Paper 1

*Architectural Simplification and Internal Software Quality in a Unity-Based
Serious Game: A Comparative Case Study*

Everything needed to re-derive every number reported in the manuscript.
Operational definitions are in `docs/paper_1_ES_arch_prism/PROVENANCE.md`;
claim-to-evidence mapping is in `TRACEABILITY.md` beside it.

The intervention code was implemented with an LLM-based coding assistant under
per-stage human review and approval; the manuscript discloses this in its
Methods (subsection *Use of an LLM-Based Coding Assistant*), Threats to
Validity, and Declarations, consistent with the records in `docs/paper/`.

---

## Quick check

```bash
cd Tools/static-analysis/analise
python verify_paper.py
```

Re-derives all 142 published values from the raw records and compares each with
the figure printed in the paper. Exit code 0 means every number in the
manuscript is reproducible from the data in this package. No Unity, .NET or
network access is required — it reads CSVs with the Python standard library.

```
C  → D0    effect of removing dead code          (control)
D0 → D     effect of the architectural intervention  (principal comparison)
C  → D     total observed transformation
```

**D0 is a control checkpoint, not a third competing architecture.**

`state-{C,D0,D}-<commit>.zip` in this directory carry `Assets/Scripts` and
`Assets/Resources/Data` at each commit — the measured population and the
datasets that drive it. They are self-contained, so the states can be inspected
without cloning the repository or resolving its history.

Third-party material under `Assets/` (LeanTween, TextMesh Pro and others) is
deliberately **not** included: it is not part of the measured system and is not
ours to redistribute. See `LICENSE` at the repository root.

## Re-running the validation suite

```bash
dotnet test Tools/characterization/Molz.Characterization.csproj
```

That runs against the state currently checked out. For C and D0, check out the
commit in a worktree first. The suite grew during the intervention — 68 tests at
C and D0, 118 at D (103 behavioural plus 15 architecture invariants) — so the
expected count depends on the state. `evidence/*.trx` records each run.

The suite establishes that **the behaviour it covers** was preserved. It is not
a proof of functional equivalence, and the manuscript does not claim one.

## Two things to know before reading the numbers

**Engine dependency** is the count of types whose declared base list contains
`MonoBehaviour` or `ScriptableObject` — types the engine itself instantiates.
It is **not** a count of types that reference `UnityEngine`: in state C,
thirteen further types use engine APIs without being counted. The check is
syntactic and considers only directly declared base types.

**Coupling** is an approximation, not Martin's $C_e$. The instrument counts
distinct capitalised identifiers inside a type declaration, without resolving
symbols. It over-counts (invoked method names, properties, enum members) and
under-counts (dependencies expressed without a capitalised identifier). It is
used comparatively, because the same rule applies to all three states; its
absolute level is not a dependency count.

Both definitions, with the evidence establishing them, are in `PROVENANCE.md`.

## SARIF

`sonar-sanitised.sarif` is the publishable form: absolute paths carrying the
operating-system user name are rewritten to repository-relative, third-party
results (LeanTween, QuickOutline, EasyLoadingScreen) are removed, and
invocation records carrying the working directory are stripped.

The surviving counts — C 197, D0 191, D 143 — match the figures in the
manuscript, which is the cross-check that the sanitising filter reproduces the
pipeline's own filtering.

Regenerate with:

```bash
cd Tools/static-analysis/analise && python sanitize_sarif.py
```

The unsanitised `sonar.sarif` stays in the repository so the pipeline output
remains auditable. **Do not publish it.**

These analyzer counts are auxiliary pipeline output. The manuscript does not
use them to answer any research question; interpreting individual findings
belongs to a separate study.
